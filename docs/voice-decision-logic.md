# 语音导览的判断逻辑

本文说明语音导览在每个环节**按什么条件、什么顺序做判断**，多个信号冲突时以谁为准。数值都取自代码；要调整，改表格里列出的常量即可。

各模块的安装、启动和参数总表见 [README 第 6.5～6.7 节](../README.md#65-雷达人群感知)。

---

## 1. 总览：一句话从进来到执行

```
麦克风 ─► 回声消除 ─► VAD 切句 ─► 识别成文字
                                     │
               ┌─────────────────────┴─────────────────────┐
               ▼                                           ▼
     机器人正在说话？（打断判断，§3）            唤醒判断（§2）
                                                           │
                                                           ▼
                         快速停止 / 再见 预处理（§4）
                                                           │
                                                           ▼
               大模型在线？──是──► 大模型 + 工具调用（§5）
                    │否                     │ 出错
                    ▼                       ▼
               离线规则（§6）  ◄────────────┘
                                                           │
                                                           ▼
                         导航 / 手势 / 风格切换 / 说话
```

同时还有两路**不经过麦克风**的输入：

- **机器人事件**：到站、受阻、传感器中断，经 rosbridge 回传（§7）。
- **相机手势**：手掌、挥手、竖拇指、比数字（§9）。

### 1.1 信号优先级

多个信号同时出现时，按下表从上到下处理：

| 优先级 | 信号 | 效果 | 代码 |
|---|---|---|---|
| 1 | 手掌手势 | 任何时候都生效：立即停嘴、停车，结束当前讲解 | `engine.on_gesture` |
| 2 | 语音里的停止词 | 先直接发停车指令（约 5 ms），再交给大模型回话 | `engine._run_turn` |
| 3 | 插话打断 | 停止播放，丢弃正在生成的回复，处理新的一句 | `engine._ear` |
| 4 | 语音指令 | 正常一轮对话 | `engine.handle_heard` |
| 5 | 其他手势（挥手、竖拇指、数字） | **只在已唤醒且机器人没在说话时**生效，否则忽略（语音优先） | `engine.on_gesture` |
| 6 | 机器人事件 | 排队，等前面的对话做完再处理 | `engine._on_robot_event` |
| 7 | 人群变化（观众离开） | 讲解中才检查 | `engine._crowd_tick` |

## 2. 唤醒：这句话要不要理

只有开启唤醒（`--wake` 或界面勾选，或唤醒方式选"视觉唤醒"）时才有这一步；不开启时所有话都处理。

```
已唤醒？──是──► 处理，并把唤醒期延长 30 秒
   │否
   ▼
句首有"小吉"？──否──► 忽略，日志 [待唤醒]
   │是
   ▼
视觉唤醒模式？──否──► 唤醒
   │是
   ▼
有相机数据？──否──► 按直接唤醒处理（只提示一次）
   │是
   ▼
最近 2 秒内，3 米内有人正对机器人？──否──► 忽略
   │是
   ▼
唤醒：只说了唤醒词 → 立即回"我在，请说。"（不调大模型）
      唤醒词后面还有话 → 去掉唤醒词，把剩下的当指令处理
```

### 2.1 "句首有小吉"怎么判断（`engine.strip_wake`）

1. 去掉标点后，句子必须**以"小吉"开头**，或以"你好 / 您好 / 嗨 / 喂 / 哈喽 / 嘿"＋"小吉"开头。句中出现不算，所以"这个小吉……"不会唤醒。
2. **按读音比**：把字转成拼音，前两个音节是 `xiao ji` 就算。所以识别成"小鸡""晓吉""小机"也能唤醒。
3. 第三个音节是 `qi` 时不算，排除"小机器人"。
4. 已知的误唤醒：句首说"小鸡在吃米"会被唤醒，这是按读音匹配的代价。

### 2.2 唤醒状态什么时候结束（`engine.keep_session`）

| 情况 | 结果 |
|---|---|
| 机器人在说话、在思考、队列里有待处理的话，或导航处于移动类状态 | 每 0.05 秒续期，保持唤醒 |
| 30 秒没人说话（`WAKE_IDLE_S`） | 休眠 |
| 游客说了再见类的话（再见、拜拜、谢谢你、我走了） | 这一轮回复说完后立即休眠 |
| 讲解中观众全部离开（§8.3） | 挥手告别后休眠 |
| 在界面里打字 | 视为已唤醒 |

"移动类状态"指 `requested / aligning / moving / blocked / backing_up`：机器人走路期间即使没人说话也不会睡着，到站后能正常讲解。

## 3. 回声与插话打断：这是不是机器人自己的声音

### 3.1 不开插话打断（默认）

机器人说话或思考时**直接关麦克风**；说完后再等 0.3 秒（`MUTE_TAIL_S`）才重新开，避开房间里的余音。这样不会误打断，但游客也没法插话。

### 3.2 开插话打断（`--barge-in`）

麦克风一直开着，靠两层过滤分辨"游客在说话"和"机器人自己的回声"：

**第一层：回声消除**（`aec.py`）。把扬声器正在播放的声音交给 WebRTC AEC3，从麦克风信号里减掉。

**第二层：文字比对**（`engine.is_echo`）。把识别出的文字和机器人"正在说 / 已排队 / 最近 5 秒说过"的话比较：

1. 两边都先把数字读成中文（`23.5` → 二十三点五），因为识别结果里是阿拉伯数字，机器人念的是中文。
2. 转成拼音，再把容易混淆的音归为一类：zh/z、ch/c、sh/s、n/l、r/l、f/h、ing/in、eng/en、ang/an、x/s、q/c、j/z。
3. 取相邻两个音节组成"音节对"，计算识别结果的音节对有多少比例出现在机器人的话里。
4. 比例 ≥ 50%（`ECHO_OVERLAP`）就判为回声。

之所以按读音而不是按汉字比：实测外放时回声"地球仪的轴是倾斜的"被识别成了"秋仪的轴式清晰"，按汉字几乎对不上，按读音大部分能对上。

**打断的条件**（机器人说话期间，每 0.4 秒检查一次最近 1.5 秒的声音）：

| 条件 | 值 | 常量 |
|---|---|---|
| VAD 判断正在有人说话 | — | — |
| 识别出的字数 | ≥ 4 个 | `BARGE_MIN_CHARS` |
| 不是回声 | 拼音重合度 < 50% | `ECHO_OVERLAP` |
| 连续满足的次数 | 2 次（约 0.8 秒） | `BARGE_CONFIRM` |

全部满足才打断：停止播放，丢弃正在生成的回复，并保留打断前 1 秒的录音拼到下一句开头，避免游客的头几个字丢掉。

**说完一整句后的过滤**：机器人还在说话时，听到不足 4 个字的短句（"不""没有"）直接忽略；拼音重合度 ≥ 50% 的整句也忽略，日志记为 `[回声]`。

实测（合成语音模拟）：戴耳机约 0.6 秒停，外放约 0.9 秒停，只有回声时不会误停。外放音量很大时仍可能误打断，演示建议戴耳机。

## 4. 进入对话前的两条硬规则（`engine._run_turn`）

这两条不等大模型，直接由程序执行：

| 条件 | 动作 | 原因 |
|---|---|---|
| 话里有停止词：停、等一下、等等、别走、站住、先别、暂停 | **先**发停车指令，再把这句话交给大模型回复 | 交给大模型要等约 3 秒才停；直接发只要约 5 ms（仿真实测） |
| 话里有再见类词 | 标记"本轮说完后休眠" | 道别后不再响应周围的闲聊 |

## 5. 大模型怎么决定做什么

### 5.1 用大模型还是离线规则（`llm.ResilientBackend`）

```
有 API Key 且不在冷却期？──否──► 离线规则
   │是
   ▼
调用大模型：连接 4 秒超时（失败自动重试 1 次），整体 10 秒超时
   │
   ├─ 成功 ──► 用大模型的回复和工具调用
   │
   └─ 失败 ──► 进入 30 秒冷却期（期间每句直接用离线规则，不再等超时）
                ├─ 还没说出任何字 → 这句改用离线规则回答
                └─ 已经说了半句   → 补一句"……抱歉，网络断了一下。"
```

| 常量（`llm.py`） | 值 | 原因 |
|---|---|---|
| `CONNECT_TIMEOUT` / `CONNECT_RETRIES` | 4 秒 / 1 次 | 本机到 DeepSeek 的 TLS 握手约 10 次失败 1 次，重试一次就能让偶发失败不影响游客 |
| `REQUEST_TIMEOUT` | 10 秒 | 游客不会等更久 |
| `OFFLINE_COOLDOWN` | 30 秒 | 断网时不让每句话都等 10 秒超时 |
| `MAX_HISTORY` | 30 条 | 只保留最近的对话；截断时一定从游客的一句话开始，不拆散工具调用和结果 |

国内厂商（DeepSeek、通义千问）自动绕过本机代理直连：走代理每次多约 2 秒。

### 5.2 每句话发给大模型的内容

每条消息前都加上当前风格标签，例如：

```
[风格：儿童模式，幽默6/10] 青花是怎么烧出来的？
```

系统提示词规定这个标签不是游客说的话，不能念出来。万一大模型在回复开头复述了标签，输出时会被 `dialog.TagFilter` 过滤掉（流式输出时也能处理被拆成几段的标签）。

### 5.3 工具调用规则（写在系统提示词里，`dialog.build_system_prompt`）

| 工具 | 什么时候调用 |
|---|---|
| `goto_exhibit` | 游客**明确想去**，或**同意了推荐**。只是问问题不算。参数只能是 E01～E06，由接口的枚举限定，大模型编不出不存在的展位 |
| `stop_robot` | 游客说停、等一下、别走了 |
| `get_robot_status` | 游客问"到了吗""去哪" |
| `set_style` | 游客要求换讲解风格或幽默程度，见 §8 |
| `gesture` | 跟说话一起做：打招呼和道别挥手；到站讲解先指向再做讲解动作；讲完等提问时放下手。移动途中和调用 `goto_exhibit` 的同一轮不做 |

### 5.4 一轮对话里调用了工具之后（`dialog.GuideDialog.turn`）

| 情况 | 处理 |
|---|---|
| 调用了导航或风格工具，而且已经说了话（如"请跟我来"） | 执行工具后本轮结束，结果随下一轮发给大模型，省一次往返 |
| 只调用了工具、还没说话 | 把工具结果发回大模型，让它接着说 |
| 调用了手势 | 把结果发回，让它把没说完的讲解说完（到站讲解常是"我们到了"＋指向＋正文） |
| 最多来回 | 3 次（`MAX_TOOL_ROUNDS`），防止死循环 |

## 6. 离线规则怎么理解一句话（`fallback.RuleBackend.respond`）

没有大模型时，按下面的顺序**逐条检查，命中第一条就返回**。顺序本身就是判断逻辑：越靠前的越优先。

| 顺序 | 判断 | 动作 |
|---|---|---|
| 0 | 消息带 `[系统事件]` | 按事件回答（§7） |
| 1 | 风格词：简单点、小朋友、听不懂、我是小孩 → 儿童；专业一点、详细讲、深入一点 → 专业；正常讲 → 普通；幽默一点、搞笑 → 幽默 +3；严肃点、正经点 → 幽默归零 | 切换风格 |
| 2 | 上一句机器人在推荐展品，这句话 ≤ 6 个字、没提到别的展品：含"不、算了、不用、别" → 拒绝；含"好、可以、行、走吧、嗯、要、是的、对" → 出发 | 确认或拒绝推荐 |
| 3 | 停止词 | 停车 |
| 4 | 再说一遍、没听清 | 重复上一句 |
| 5 | 下一个、下一站、接下来 | 去当前展品推荐的下一站；还没看过展品就去 1 号 |
| 6 | 提到了展品 + 带我 / 去 / 领我 / 想看 / 参观，且**没有**"为什么、怎么、什么" | 去该展品 |
| 7 | 提到了展品 + 在哪 / 怎么走，且不是在问原作（原画、真迹、收藏在） | 问要不要带过去 |
| 8 | 提到了展品 + 感兴趣 / 喜欢 / 想了解 | 讲一句，再问要不要带过去 |
| 9 | 继续走、走吧，且之前有目的地 | 继续去原目的地 |
| 10 | 有什么展品、有哪些 | 列出全部展品 |
| 11 | 你是谁、叫什么 | 自我介绍 |
| 12 | 再见类词 | 道别并挥手 |
| 13 | 你好类问候，且整句 ≤ 6 个字 | 打招呼并挥手 |
| 14 | 以上都不是 | 当作问题，去知识库找答案（§6.2） |

第 6 条排除"为什么、怎么、什么"，是为了让"青花瓷是怎么烧的"被当作提问，而不是"去看青花瓷"。

### 6.1 认出游客说的是哪件展品（`find_exhibit`）

1. 先找编号说法："第三个""三号""E03"。
2. 再找展品名和 `knowledge/E0*.md` 里的别名，取**匹配到的最长的名字**。例如"带我去看太阳和地球"里同时有"太阳和地球"（E01 别名）和"地球"，取更长的那个。
3. 名字 ≥ 3 个字时**允许错一个字**，用来容忍识别的同音错字："的球仪"也能匹配"地球仪"。

### 6.2 回答问题（`FaqIndex.search`）

1. 把问题和每条"常见问题"（问题文字算两遍，加上答案）都拆成单字和相邻两字，用 TF-IDF 加权后算余弦相似度。
2. 游客提到的展品，或正在讲的展品，排名时加 0.1（`CONTEXT_BONUS`）。这样"它的釉是什么颜色"会优先在当前展品里找。
3. 判断"答不答"只看**原始分数**，必须 ≥ 0.15（`FAQ_THRESHOLD`）。加分只影响排名，不能让无关的问题勉强过线。实测美术馆这套资料里，无关问题一般 ≤ 0.13，真正的问题 ≥ 0.28。
4. 没过线时：
   - 提到了展品且是"介绍、讲讲、是什么" → 读讲解正文的前几句；
   - 提到了展品 → 说不确定，建议问原理、用途，或带过去看；
   - 什么都没提到 → 说只能回答展品相关的问题。

## 7. 机器人事件（`robot.RobotLink._on_status`）

导航节点每 0.5 秒左右在 `/nav/status` 发布一次状态。只有下面几种状态会通知对话，并且**每个目标只通知一次**：比如 `blocked` 在 A* 反复重试时会重复出现，只报第一次；收到新目标（`requested`）后清零重新计数。

| 状态 | 发给对话的内容 |
|---|---|
| `arrived` | "已到达某展品，请开始讲解"（开启人群感知时先走 §8.2 的流程） |
| `blocked` | 路被挡住，正在重新规划，请简短说明 |
| `invalid_goal` | 导航目标无效 |
| `sensor_stale` | 传感器数据中断，请致歉 |

这些消息以 `[系统事件]` 开头，系统提示词规定它们不是游客说的话。

## 8. 讲解风格：什么时候用儿童模式

风格有两个维度：**讲解对象**（普通 / 儿童 / 专业）和**幽默值**（0～10）。

### 8.1 风格由谁决定（优先级从高到低）

| 来源 | 能设什么 | 设了之后 |
|---|---|---|
| ① 游客亲口要求（大模型调用 `set_style`，或离线规则命中风格词） | 讲解对象、幽默值 | 讲解对象标记为"手动"，雷达**不再自动改** |
| ② 操作员在界面里选，或启动参数 `--audience` / `--humor` | 讲解对象、幽默值 | 界面选择同样标记为"手动" |
| ③ 雷达自动判断（§8.2） | **只能**在普通和儿童之间切换 | 每次到站重新判断 |

- **专业模式**和**幽默值**从不自动设置，只能由游客要求或操作员设定。
- "手动"标记在观众全部离开、机器人挥手告别后清除（`engine._goodbye`），下一批游客重新自动判断。

### 8.2 自动判断儿童：从雷达点云到儿童模式

需要真机规格雷达（`lidar:=mid360`），并勾选界面上的"按雷达人数讲解"。

**第一步：从点云里找人**（`people_core.detect_people`，WSL 端）

| 步骤 | 规则 | 参数 |
|---|---|---|
| 去掉地面 | 离地 < 0.15 m 的点丢弃 | `min_height` |
| 去掉自己 | 离机器人 ≤ 0.75 m 的点丢弃（指向手势时手伸到前方约 0.5 m，曾被当成一个 0.97 m 高的"儿童"） | `self_radius` |
| 只看附近 | 最远 6 m | `range_max` |
| 去掉静态物体 | 落在墙、展台等已知几何里的点丢弃 | `StaticGeometry.hit` |
| 聚类 | 按 0.3 m 网格分格，相邻的格连成一簇 | `cell` |
| 太稀的不要 | 一簇至少 4 个点 | `min_points` |
| 按高度筛 | 簇顶离地 0.7～2.05 m 才算人：更矮的是包、长椅，更高的是门框 | `min_top` / `max_top` |
| 按宽度估人数 | 宽度 > 0.7 m 按多人算（人数 = ⌈宽度 ÷ 0.7 − 0.2⌉）；宽度 > 2.5 m 是家具，不算人 | `person_width` / `max_extent` |

**第二步：判断身高能不能测全**

MID-360 倒装在机器人头部，约 1.27 m 高，向上只能看约 7°。在距离 d 处，雷达能看到的最高点是：

```
可见上限 = 1.27 m + d × tan(7°)      （3 米外约 1.64 m）
```

簇的最高点距离这个上限不到 0.08 m 时，说明头顶被视野截断了，标记为"身高被截断"（`height_clipped`），测到的高度只是下限。**成人通常都会被截断，儿童比雷达矮，能测出完整身高**，正好用来区分大人和小孩。

**第三步：跨帧跟踪，判断是不是儿童**（`people_core.Track.child`）

同一个人在相邻帧之间移动不超过 0.8 m 就算同一个人，短暂丢失 0.6 秒内仍保留编号。每个人记录最近 15 帧的身高，满足下面**全部**条件才算儿童：

| 条件 | 目的 |
|---|---|
| 这一簇只有 1 个人 | 几个人挤在一起时，量出来的高度不代表某一个人 |
| 15 帧里**一次都没有**被截断 | 只要有一帧头顶出了视野，就可能是成人 |
| 15 帧里的**最大**身高 < 1.30 m（`CHILD_MAX_HEIGHT`） | 用最大值而不是平均值：弯腰、被遮挡只会让高度偏低，取最大值不容易把成人误判成儿童 |

**第四步：决定讲解对象**（`voice/crowd.audience_for`）

| 3 米内的人 | 讲解对象 |
|---|---|
| 正好 1 个人，而且是儿童 | **儿童模式** |
| 1 个成人 | 普通模式 |
| 2 个人以上（不管有没有儿童） | 普通模式 |
| 讲解对象已被游客或操作员手动设定 | 保持手动设定，不改 |

人数按"每簇估计的人数"相加，不是按簇的个数。

**为什么有人群就不切儿童模式**：家长带孩子是最常见的情况，切成儿童模式会让大人觉得讲得太浅。只有一个孩子单独在听时才切换。家长想要儿童模式，可以直接说"讲简单点"。

**切换儿童模式后的变化**：大模型按儿童要求说话（短句、生活比方、多问"你知道吗"、不用术语、数字取整）；离线语音语速降到 0.85（`CHILD_SPEED`）；离线规则的到站讲解只读 2 句（普通 4 句，专业读全文）。

### 8.3 到站讲解流程（`engine._arrive`）

```

有雷达人群数据？──否──► 直接讲（和没有人群功能时一样）
 │是
 ▼
3 米内有人？──是──────────────────────────────┐
 │否                                          │

说"大家跟上了吗？"，最多等 10 秒               │

                                              │
```

### 8.4 幽默值

| 值 | 系统提示词里的要求 |
|---|---|
| 0 | 完全严肃 |
| 3 左右（默认） | 偶尔轻松一句 |
| 6 以上 | 多用俏皮比喻和小玩笑 |
| 9 以上 | 像脱口秀 |

任何幽默值下知识都必须准确，不拿游客开玩笑。"幽默一点"在当前值上 +3，"严肃点"归零，范围限制在 0～10。离线规则不会说笑话，只记录这个值。

## 9. 视觉信号（Windows 端 `vision/watch.py` → `/guide/vision`）

### 9.1 "有人正对机器人"（视觉唤醒用）

1. 人脸检测后，看这张脸是不是正脸（`vision_core.face_facing`）：
   - 两眼间距 ≥ 脸宽的 25%（侧脸时两眼间距会变小）；
   - 鼻尖偏离两眼中点 < 两眼间距的 35%（转头时鼻尖会偏）。
2. 把人脸和雷达里的人对应起来（`crowd.facing_people`）：方位角相差 ≤ 8° 的算同一个人，距离取雷达测的。如果按脸宽估的距离超过雷达距离的 2.5 倍，说明这张脸是站在那个人后面更远的另一个人，不算。
3. 没有雷达数据时，直接用脸宽估的距离。
4. 3 米内有正脸，记为"有人正对机器人"；视觉唤醒要求这件事发生在说唤醒词前 2 秒内（`VISION_WAKE_WINDOW_S`）。

### 9.2 手势（`vision/gestures.py`）

| 手势 | 判断 | 触发 |
|---|---|---|
| 手掌 | 四指和拇指都伸直，手不动，保持 0.5 秒 | 停止讲解并停车（**任何时候**都生效） |
| 挥手 | 五指张开，2 秒内手腕左右摆动至少 2 次，幅度 ≥ 0.6 个手掌宽 | 讲解中是"再见"，否则是"你好" |
| 竖拇指 | 只伸拇指，且拇指基本竖直朝上 | "好的"（例如同意推荐） |
| 比 1～4 | 不伸拇指，从食指开始依次伸出 1～4 根手指，保持 0.5 秒 | 去 1～4 号展位（五指张开是手掌，所以只能数到 4，5、6 号用语音） |

"手指伸直"的判断：指尖到手腕的距离 > 指中关节到手腕距离的 1.15 倍。静止手势要持续 0.5 秒且至少 2 帧才触发，同一个手势保持不动时只触发一次。

除手掌外，手势要求**已唤醒且机器人没在说话**，否则忽略：语音比手势优先。
